# HPGT flysteder – spesifikasjon

Ny versjon av flysteder.hpgt.com. Erstatter den gamle iframe-baserte flystedsoversikten til Lars Sletten, som han har gitt til klubben. Målgruppe: ferske PP2-piloter og tilreisende piloter. Norsk og engelsk (`/en/`), med struktur for flere språk (se [docs/arkitektur.md](docs/arkitektur.md#språk)).

## Teknisk oppsett
- Statisk side bygget med **Eleventy (11ty)**. Ingen server, ingen database.
- Publiseres på **GitHub Pages** via GitHub Actions ved push til `main`. Eget domene `flysteder.hpgt.com` settes i Pages-innstillingene (CNAME).
- `actions/checkout` med `fetch-depth: 0`, så «sist endret» per sted kan hentes fra Git.
- Kart: **Leaflet**, installert via npm og servert fra egen side. Standard bakgrunn: Kartverkets åpne topografiske kart. Kartverkets fliser er gjennomsiktige utenfor Norge, så OpenTopoMap ligger under og fyller ut resten av verden. Alternative lag: OpenTopoMap og satellittbilde fra Sentinel-2 cloudless (EOX, 10 m oppløsning, CC BY-NC-SA 4.0, ikke-kommersiell bruk). Flyfoto fra Norge i bilder er bedre, men krever tillatelse (forespurt hos Kartverket). Kreditering av kartkilder.
- PR-sjekken (`pr-check.yml`, jobben `build`) kjører testene (`npm test`) og bygger siden. Bygget skal feile hvis en stedsfil er ugyldig (manglende `name`, ugyldig retningskode, ukjent nøkkel, bilde som ikke finnes).
- Automatiske importer (Kartverket-høyder, luftrom fra openAIP) skriver aldri i stedsfilene, bare i `src/_data/cache/`.
- Luftrom hentes fra openAIP (CC BY-NC 4.0) med `npm run airspace`, i én eller noen få sirkler som dekker alle startene (openAIP har streng fartsgrense og avviser for stor radius, så sirklene er høyst 150 km), og lagres per start og som `region.geojson` til kartlaget. Hentes og av workflowen «Update airspace» (`airspace.yml`) den 1. hver måned. Endringer kommer som PR og gjennomgås før merge. Nøkkelen ligger som repository secret `OPENAIP_API_KEY`. Stedsfilens `airspace` brukes bare til steder som ikke er hentet ennå, og til merknader (`note`).

## Innhold
- Én mappe per sted: `src/flysteder/<id>/index.md` med front matter + tekst, og bilder/GPX i samme mappe.
- Faste filnavn med stedets id foran, som bygget håndhever: bilder heter `<id>-overview-<nr>`, `<id>-takeoff-<retning>-<nr>` (f.eks. `elgen-takeoff-se-1`, retning kan mangle), `<id>-landing-<nr>` og `<id>-landing-spg-<nr>` (`.jpg`, `.png` eller `.webp`). Bygget finner bildene ut fra navnet (`lib/site-images.js`), så stedsfilen har ingen liste over bilder, og et bilde med feil navn stopper bygget. Gangruter heter `<id>-route.gpx`, eller `<id>-route-1.gpx`, `<id>-route-2.gpx` osv. når stedet har flere ruter. Filer fra Strava eller kamera må døpes om før de legges inn. Bilder importeres med `npm run images`, som gir riktig navn, skalerer ned til maks 2560 px og fjerner metadata (EXIF/GPS).
- **Navngiving av innsamlede bilder** (`lib/photo-name.js`), så sted, type og retning kan leses fra filnavnet:
  - `<Location>_Takeoff_<Direction>_<Nr>_<Original>.jpg`, for eksempel `Storlitinden_Takeoff_SE_1_DSC04968.jpg`
  - `<Location>_Landing_[SPG_]<Nr>_<Original>.jpg`, for eksempel `Storlitinden_Landing_1_DSC05012.jpg` eller `Sollifjellet_Landing_SPG_1_DSC00978.jpg`
  - `<Location>_Overview_<Nr>_<Original>.jpg`, for eksempel `Storlitinden_Overview_1_DJI_0042.jpg` (`Aerial` godtas også, for bilder som allerede har det navnet)
  - Location er stedsnavnet uten mellomrom, bindestrek og æ/ø/å («Melå aksla» → `MelaAksla`, æ kan skrives ae, a eller e, ø som oe eller o og å som aa eller a). Retning bare på Takeoff: én engelsk kode (`N`, `NE`, `E`, `SE`, `S`, `SW`, `W`, `NW`), retningen man ser mot når man starter. Landing og Overview har ingen retning, siden den ville vært vilkårlig. **Overview er oversiktsbildet** («Oversikt» på siden, `<id>-overview` i repoet): et bilde som viser hele stedet, helst fjellet man tar av fra sett fra luften, ellers fra landingen opp mot starten eller utsikten fra starten. Overview nr 1 er stedets hovedbilde og forhåndsbildet når siden deles. `SPG` er et valgfritt merke, bare på Landing, for landinger som er egne for SPG (Sollifjellet: SPG-landingen i skogen). Alle landinger er PG, så det skrives ikke. Nr er 1, 2, 3 … innenfor samme sted og type. Original er kameraets filnavn.
  - `npm run images -- <filer eller mappe>` leser navnene, finner stedet og importerer alle bildene. Type, retning, SPG og nummer blir med i navnet i repoet: `Storlitinden_Takeoff_SE_2_DSC04970.jpg` blir `storlitinden-takeoff-se-2.jpg`. Har ett av bildene feil navn (ukjent sted, norsk retning som SØ, retning på landing, manglende nummer), eller blir to bilder samme fil, importeres ingenting, og meldingen sier hva som er galt. Finnes bildet allerede, hoppes det over, så samme mappe kan importeres flere ganger. `--replace` bytter dem ut.
- Import av enkeltbilder uten konvensjonen: `npm run images -- <id> <felt> <fil>`. Bildet får neste ledige nummer for feltet, uten retning.
- **Fotograf og lisens** (`lib/photo-credit.js`, `src/_data/photoCredit.json`, `LICENSE_IMAGES.md`): bildene er CC BY-NC 4.0. Importen fjerner all metadata (GPS, kamera, redigeringshistorikk) og skriver bare tilbake fotograf, copyright, nettside og lisens (EXIF Artist/Copyright med bare ASCII, XMP dc:creator, dc:rights, xmpRights:WebStatement, cc:license og nettside, med æøå og ©). Fotografen leses fra originalen (som Lightroom skriver den), ellers brukes standarden: Kristoffer D. Hofstad, «© Kristoffer D. Hofstad | Hofstad.NET | @krishofs», https://hofstad.net. Bildene som lages ved bygging, får de samme feltene. Synlig: «Foto: Navn · CC BY-NC 4.0» under bildene på stedssiden og i bildevisningen, med lenke til fotografens nettside og lisensen. `npm run images` legger fotograf og lisens inn i bilder i repoet som mangler det. Originaler over 2 MB stopper bygget. Siden viser bare versjoner laget ved bygging (WebP/JPEG i flere størrelser), aldri originalene. Det finnes ikke lenger oversiktsbilder: Lars sine tegnede bilder fra Google Earth er fjernet, og kartet med retningsbuer og punkter har tatt over.
- Front matter følger strukturen i eksisterende filer (se `src/flysteder/elgen/index.md` for et komplett eksempel). Nøklene er på engelsk, verdiene på norsk. `parking` er en liste (steder kan ha flere ruter med hver sin parkering). Hver linje under `launches` kan ha `categories` (PG/SPG).
- Retninger lagres som standardkoder (N, NE, E, SE, S, SW, W, NW) og vises som norske (N, NØ, Ø, SØ, S, SV, V, NV).
- `status: utkast` betyr at stedet vises, men merkes «Ikke gjennomgått ennå». Når stedet er kontrollert, settes `status: gjennomgått` sammen med `reviewed.by` (navn) og `reviewed.date` (`'2026-09-24'`). Bygget feiler hvis status og `reviewed` ikke stemmer overens.
- Tomme felt (`null`) vises som tydelige plassholdere eller utelates, aldri som gjettede verdier.
- Statussiden `/status/` viser hvilke steder som er gjennomgått, og hva som mangler per sted (nivå, landing (ikke når `no_fixed_landing: true`), parkering, parkeringstekst, gangrute (ikke når en parkering ligger under 300 m fra starten og under 50 m lavere, med høyden i parkeringens `masl`), starttekst, landingstekst, høyder, bilder, luftrom, yr_id, flightlog_id, engelsk tekst og utdatert engelsk tekst). Se [docs/drift.md](docs/drift.md#statussiden). Den lages automatisk ved hver bygging, lenkes ikke fra menyen og er merket `noindex`. Den erstatter `MANGLER.csv`.
- `external.pgearth_id` settes manuelt, bare når stedet faktisk finnes på Paraglidingearth. Ingen import derfra: API-et er bare for lesing, bare 5 av 30 steder finnes der, dataene deres avviker fra våre, og innholdet er lisensiert med «del på samme vilkår» (CC BY-SA 3.0 / ODbL). Bidrag til Paraglidingearth gjøres manuelt på nettsiden deres, og bare med innhold klubben har rett til å dele.

## Forside
- Tittel «Hvor står vinden i dag?». Menyknapp (tre streker) oppe til høyre på alle sider med språkvalg (Norsk/English, lenker til samme side på det andre språket), fargemodus (Auto/Lys/Mørk), bryter for fargeblindvennlige farger og lenkene «Alle flysteder» og «Til hpgt.com».
- **Søk etter flysted** øverst i filtrene: filtrerer listen og kartet mens man skriver, sammen med de andre filtrene. Uten hensyn til store/små bokstaver og aksenter, æ/ø/å kan skrives ae/o/a, mellomrom og bindestrek teller ikke, treff hvor som helst i navnet («solli» → Sollifjellet). Opptil 6 treff vises som knapper rett under feltet (ellers antallet), kartet zoomer til treffene. Enter med ett treff velger stedet, Esc tømmer. Lagres i adressen som `q=`.
- Filtre som virker sammen: **vindretning** (kompass 3×3 med «Alle» i midten), **nivå** (Alle, PP2–PP5, viser valgt nivå og lavere), **kategori** (Alle, PG, SPG, PPG). Med en kategori valgt brukes retningene til startene for den kategorien (`launches[].categories`), i retningsfilteret, rosen og vindvurderingen: SPG på Elgen starter bare mot NØ–SV. Steder uten registrert nivå skjules ikke av nivåfilteret: de vises nederst i listen under «Nivå ikke satt», litt nedtonet i kartet, og telles for seg («3 flysteder passer filtrene, 25 uten nivå»).
- Kart med alle starter som små vindroser (hvite skiller, mørk kant, stedsnavn under rosene når man zoomer nært inn). Starter som ligger oppå hverandre når man zoomer ut, slås sammen til en klynge med antall steder som passer filteret (Leaflet.markercluster); klikk zoomer inn. Med vind på har klyngen ringfargen til den beste vurderingen i den. Luftromslag som i IPPC kan slås av og på i kartets lagvelger: CTA/TMA, CTR, militære områder, fare og restriksjon. Av som standard, lastes først når de slås på («Laster luftrom …», ved feil «Kunne ikke hente luftrom» med «Prøv igjen»), klikk viser navn, klasse og grenser. Kreditering «Luftrom: openAIP … Ikke for navigasjon, sjekk IPPC». Termikklag (også på stedssidene): «Termikk: skyways» og «Termikk: hotspots» fra thermal.kk7.ch (CC BY-NC-SA 4.0, statistikk fra loggede flyturer, ikke varsel), av som standard. Ingen værradar, den sjekkes i Yr/Windy. Steder som ikke passer filteret tones ned. Klikk på en start viser et kort med rose, tagger, kort tekst, «Se hele stedet» og «Se på Flightlog». Kartet åpner over startene i hjemregionen (`homeRegion` i `src/_data/site.js`, «Harstad og Kvæfjord», som også dekker Grytøya), ikke over alle stedene, så steder langt unna (Lofoten, Andøya, Andørja, Bjerkvik) ikke zoomer kartet ut. De finnes i listen og søket. Under zoomknappene: «Vis flysteder i Harstad og Kvæfjord» (hus, tilbake til hjemregionen) og fullskjerm, samme knapper som på stedssiden (`addViewControls` i common.js).
- **Kontroller**: vindtidspunkt, nivå og kategori som segmenterte linjer (alle valgene på én rad: `Av | Nå | +3 t | +6 t | I morgen`), forslaget som bryter («Bare steder som kan passe nå»). Ingen undertittel under overskriften. På PC (mus) er kontrollene, kompasset og listen mer kompakte, så listen kommer høyere opp. Mobil beholder trykkflater på 44 px.
- **Mobil**: kompasset for retning står alltid synlig, som på PC (store knapper, og det er filteret man bytter oftest). Nivå og kategori ligger bak knappen «Nivå og kategori» (med «N valgt» når noen er valgt), så kartet og resultatene kommer tidligere. Søk og vindtidspunkt er alltid synlige. Regelteksten for vindvurderingen står bak «Hvordan vurderes vinden?». På PC vises alle filtrene.
- Forklaring til rosefargene (hovedretning, mulig, ikke egnet). Mobil: under kartet. Desktop: under kortet for valgt sted.
- **Vindvurdering** (filtergruppe «Vind fra varsel»: Av, Nå, Om 3 t, Om 6 t, I morgen kl. 12). Varsel fra MET Locationforecast for hver start (`src/_data/forecast.js`, 48 timer, hentes ved hver bygging, siden bygges to ganger i timen, men GitHub kan forsinke planlagte kjøringer). Logikken ligger i `src/assets/js/wind.js` og testes i `test/wind.test.js`. Regler i `src/_data/windRules.json`:
  - «For mye vind»: middelvind over `maxWind` (7 m/s), eller over stedets egen grense `wind_limits.max_wind` når den er satt, eller kast over `maxGust` (10 m/s).
  - «Passer ikke»: regn meldt, `rainNo` (0,5 mm) eller mer neste time (nedbør fra MET, `next_1_hours`), eller retningen er verken hovedretning eller mulig.
  - «Usikkert»: litt nedbør meldt (`rainMaybe`, 0,1 mm eller mer neste time), mulig retning, middelvind under `minWind` (2 m/s, retningen er da usikker), varselet mangler kast, kast mer enn `maxGustSpread` (4 m/s) over middelvinden, eller hovedretning der vinden ligger innenfor `sectorMargin` (10°) fra en retning som ikke er hovedretning.
  - «Kan passe»: ellers. Det som mangler eller er usikkert, gjør aldri vurderingen bedre.
  - Kortet viser vind, klokkeslett, vurdering og årsaken. Under vindvalget står hvilket klokkeslett som vises og når varselet ble hentet. Klokkeslett og «I morgen kl. 12» er alltid norsk tid.
  - Er varselet hentet for mer enn `maxForecastAgeHours` (6 t) siden, skjules vindvalget, og siden sier at varselet er for gammelt. Alderen sjekkes på nytt før hver vurdering, når man kommer tilbake til fanen og hvert minutt, så en fane som har stått åpen lenge slår av vurderingen selv. Samtidig tegnes vurderingen på nytt når valgt tidspunkt har flyttet seg til en annen time i varselet (timeskifte, og midnatt for «i morgen»). Dekker varselet ikke valgt tidspunkt, vises ingen vurdering.
  - **Forslag fra varselet**: knappen «Vis bare steder som kan passe nå» (teksten følger valgt tidspunkt) under tidsvalget toner ned steder der vurderingen er «Passer ikke» eller «For mye vind», som når man velger en retning i kompasset, og fjerner dem fra listen. «Kan passe» og «Usikkert» blir stående. Steder uten varsel (hentingen feilet for stedet) står for seg nederst i listen under «Mangler varsel – ikke vurdert», og tones litt ned i kartet som steder uten nivå. Virker sammen med de andre filtrene, er av som standard og bare tilgjengelig når vind er på. Lagres i adressen som `forslag=1`.
  - **Statuskort for kartet**, rett over kartet på mobil og halvgjennomsiktig oppå kartet (til høyre for zoomknappene) på PC: «Viser 9 av 30 flysteder», oppsummeringen av vinden og når varselet ble hentet / hvilket klokkeslett som vises. Venstremenyen har bare søk og filtre.
  - **Oppsummering** for valgt tidspunkt (i statuskortet), for stedene som passer retning, nivå, kategori og søk («For 16 steder som passer filtrene»): vinden i området (vanligste retning, middelvind fra–til, høyeste kast) og hvor mange steder som kan passe, er usikre, har for mye vind (hvor mange på grunn av kast eller stedets egen grense), feil retning og regn, og hvor mange som mangler varsel. Passer ingen, står det hvorfor (for mye vind, for kraftige kast eller feil retning), også i listen når forslaget er på.
  - Varselet hentes per sted. Feiler ett sted, står det «Ingen vindvarsel for stedet» der, og resten får vurdering. Feiler alle, vises ikke vindvalget.
  - Kartet viser farget ring, og sektoren i rosen vinden kommer fra løftes litt ut og fylles med vurderingsfargen (ingen egen vindpil), også i rosen i kortet for valgt sted, listen sorteres etter vurdering. Bare et forslag, aldri «OK å fly».
- Liste over steder som passer filteret, med starthøyde (moh) til høyre for navnet når den er registrert. Kortet for valgt sted viser også starthøyden.
- **Faner** øverst i venstrekolonnen: **Flysteder** (søk, vind, filtre og liste, med en kort linje om at det er en grov guide), **Vær** (lenker til Flybart, XCC, Yr og Windy; målt vind fra værstasjoner i kartet kommer her) og **Info** («Før du drar», ansvarsfraskrivelse, kreditering og åpne data). Kartet står alltid. Piltaster flytter mellom fanene.
- «Før du drar» (fanen Info): NOTAM og luftrom (https://ippc.no) og Tårn (egen side `/luftrom/`, `/en/towers/` på engelsk, med telefonnumre til tårnene fra `src/_data/towers.json`, tårn uten nummer vises ikke). Flybart og XCC står under Vær.
- Ansvarsfraskrivelse og kreditering av Lars Sletten (fanen Info). Krediteringen står bare her, ikke på hver stedsside.
- Desktop: to kolonner (venstrekolonne med faner | kart). Ingen høyrekolonne: statuskortet ligger øverst til venstre i kartet, kortet for valgt sted nederst til høyre (vises når et sted er valgt, lukkes med ×), og tegnforklaringen som en halvgjennomsiktig linje nederst til venstre. Mobil: faner, filtre, kart, valgt sted, tegnforklaring, liste.
- Markører (46 px): samme rose som i kortet og på stedssiden (`roseSvg` i common.js). Med vind på har ringen vurderingsfargen, og sektoren vinden kommer fra er fylt med vurderingsfargen fra midten helt ut til ringen (ingen vindpil). I kortet for valgt sted er sektoren løftet litt ut i stedet. Klynger er avrundede firkanter (40 px), så de ikke ligner de nummererte punktene på stedssidene.
- Statuskortet: «Viser N av 30 flysteder», vindlinjen, en fargelinje med fordelingen av vurderingene og antall per vurdering med fargede prikker. Detaljene (kast, stedets egen grense) står i merkelappen på fargelinjen. Passer ingen, står grunnen under.

## Stedsside – fast mal i denne rekkefølgen
1. Navn med starthøyde («Sollifjellet 567 moh») og én–to setninger kort fortalt. Kategori og sesong står bare i Fakta. Er stedet ikke gjennomgått, står taggen «Ikke gjennomgått ennå» her.
2. **Kart**, øverst under tittelen (erstatter oversiktsbildet): start som prikk med hvit kant i samme petrolblå som hovedretningen i vindrosen (rund, så den skiller seg fra parkering; retningene vises med retningsbuene og i merkelappen), landing som mørk målskive, alternativ landing som grå målskive, parkering (blå P). Starter med egen posisjon (`launches[].lat`/`lon`, valgfritt, maks 5 km fra `launch`) får hver sin prikk med sine retninger i merkelappen; hovedstarten står da for startene uten egen posisjon, og tegnes ikke hvis alle har egen posisjon. Én prikk er standard: retninger som startes fra samme sted, hører til samme start, også når den dekker mange retninger. Egen posisjon er bare for starter som ligger et annet sted (Sollifjellet: toppen, alpinsenteret, alpinbakken og baksiden). Starter, landing, parkering og nummererte punkter ligger i ett lag (Leaflet.markercluster). Starter som ligger så tett at prikkene ville overlappet, slås sammen til én prikk med antallet starter. Ligger ulike punkter oppå hverandre (for eksempel landing, P og et nummer), slås de sammen til én hvit boks med de samme symbolene i liten størrelse (prikk med antall starter, målskive, P, nummer), med navnene i merkelappen. Trykk på boksen zoomer inn til de skilles; fra zoom 16 vises alt hver for seg. Når man har zoomet langt ut (zoom 13 og lavere), slås flere sammen, siden boksene er brede. Trykk i listen «Punkter i kartet» zoomer inn til punktet vises for seg, gangruter fra GPX (stiplet linje). Knapper: Veibeskrivelse til parkering (Google Maps), Last ned gangrute (GPX).
   - **Retningsbuer** (ovenfra, i samme kart): gule buer med pil og retningsmerke for hver retning stedet passer for, regnet ut fra `wind_directions` og startenes posisjoner (`directionArcs` i `common.js`). Har startene egne posisjoner, får hver retningsgruppe (starter med samme retninger) sin egen bue der startene ligger: midt mellom dem, med radius til lengste start + 110 m. Uten egne posisjoner er det én bue rundt hovedstarten (250 m), eller rundt `direction_arc` i tegningen. Mørk gul er hovedretning, lys gul mulig. Buen holdes minst 60 px stor på skjermen og tegnes på nytt ved zoom; kartet zoomer ut til buene og retningsmerkene får plass.
   - **Tegningen** (`<id>-drawing.geojson`, valgfri, valideres ved bygging i `lib/drawing.js`, kan tegnes i geojson.io): erstatter de tegnede oversiktsbildene. `label` (punkt med title og text), `path` (linje, style launch/flight/hazard/info, dashed, arrow) og `area` (område, style hazard/launch/landing/info), og valgfri `direction_arc` (center, radius). Bare innhold klubben har bekreftet legges inn.
   - **Punkter i kartet**: nummererte punkter som viser tittel og tekst når man trykker, og en nummerert liste «Punkter i kartet» under kartet. Trykk i listen flytter kartet dit og viser teksten; trykk på et punkt markerer det i listen; fare som lys firkant med rød kant. Tallet på en gruppe sammenslåtte starter er hvitt med oransje kant, så det ikke forveksles med punktene.
   - **Vis hele stedet**: knapp med hus-symbol under zoomknappene, som går tilbake til utsnittet med alt (starter, landing, parkering, gangruter og retningsbuer).
   - **Fullskjerm**: knapp under «Vis hele stedet» som legger kartet over hele siden (ikke nettleserens fullskjerm, så det også virker på iPhone). Esc eller knappen igjen lukker. Utsnittet tilpasses når kartet bytter størrelse.
   - **Zoom**: musehjulet ruller siden; med Ctrl (Cmd på Mac) zoomer det kartet, og uten vises et kort hint. Zoomknappene og +/- på tastaturet når kartet har fokus virker som før.
   - **Høydeprofil** under Adkomst (etter Parkering/Veien opp/Tid, rett etter kartet) når stedet har gangrute: avstand/høyde, partier brattere enn 25 % markert i aksentfarge, glidebryter (og dra/touch i profilen) som flytter en markør langs ruten i kartet og viser avstand, høyde og stigning. Faner når stedet har flere ruter. Kort oppsummering under (km, fra–til moh, hvor mye som er brattere enn 25 %). Høyder bør hentes fra Kartverket, med GPS-høyde som reserve.
   - Tid under Adkomst er bevegelsestid fra GPX (uten pauser), rundet til 5 min. Har stedet én gangrute, står lengde, stigning og tid som tre tall øverst i Adkomst («1,5 km · 330 m · 35 min»), og gjentas ikke i radene under.
3. **Før du starter**: bare farer som gjelder hele stedet. Står øverst til høyre på PC (ved siden av tittelen, over Fakta) og rett etter tittelen på mobil. Rolig ravfarge med «!», ikke rødt: det er viktig informasjon til piloten, ikke en alarm (rødt er for «for mye vind»). Farepunkter i kartet har samme farge. Hvis ingen: «Ingen spesielle farer registrert for stedet.» (nøytral boks) når stedet er gjennomgått, ellers «Farene er ikke gjennomgått ennå. At ingen er registrert, betyr ikke at stedet er uten farer …». Ingen snarvei under tittelen, siden boksen synes uten å bla.
4. **Adkomst**: Parkering, Veien opp (med km og høydemeter fra GPX), Tid (bevegelsestid fra GPX), høydeprofil.
5. **Start**: kort tekst om startområdet og én linje per retningsgruppe med retningsmerker i rosens farger og kategori-tagger (PG/SPG) når stedet har mer enn én kategori, så man ser hvilke starter som brukes til SPG (for eksempel Sollifjellet: SPG fra toppen og ved toppen av heisen). Har stedet bare én kategori, settes ikke kategori per start. Starter med samme retninger og kategorier slås sammen til én linje, med tekstene under hverandre i rekkefølgen fra stedsfilen (`groupLaunches` i `lib/format.js`); kartet viser fortsatt hver start der den ligger.
6. **Landing**: kort tekst. Under står det samme for alle steder: «Se alltid over landingen før du flyr. Lander du på et jorde, må det være avtalt med bonden, og gresset må ikke være høyt.»
7. **Fakta**: vindrose med forklaring, Nivå, Kategori og Sesong (tagger) på én linje, så rader for Maks vind (bare når `wind_limits.max_wind` er satt), Høyde (start moh, landing moh, forskjell), Luftrom over start: bare taket over start, det laveste faste luftrommet over startstedet, som tagger (navn, klasse, nedre grense i ft, ca. moh regnet om fra fot), og under: dato for siste henting, og «Sjekk alltid IPPC før du flyr.» på egen linje. Bare luftrom ved takeoff vises. Nærliggende luftrom (TMA, CTR osv.) vises ikke, piloter sjekker dem i IPPC. Nærliggende og militære områder hentes, men vises ikke.
8. **Vær**: «Vind nå» for starten fra MET-varselet med samme regler som forsiden (`site-wind.js`, data i `#site-wind-data`; sier fra når varselet er for gammelt eller ikke dekker timen), Yr-meteogram som lenker til Yr (`https://www.yr.no/nb/innhold/<yr_id>/meteogram.svg`, `https://www.yr.no/en/content/<yr_id>/meteogram.svg` på engelsk, med `?mode=dark` i mørk modus, kreditering «Varsel fra Yr, levert av NRK og Meteorologisk institutt»), lenker til Windy (pin på startkoordinat: `https://www.windy.com/<lat>/<lon>?<lat>,<lon>,12`), Flybart og XCC flymet. IPPC står under Luftrom, ikke her.
9. **Bilder**: Oversiktsbilde nr 1 stort øverst (samme som forhåndsbildet når siden deles), første start og første landing mindre under. Bildetekst «Oversikt», «Start mot SØ», «Landing» eller «SPG-landing». Har stedet flere bilder, åpner «Se alle N bilder» bildevisningen med alle, i rekkefølgen oversikt, start, landing (SPG-landing sist). Bare bilder som finnes vises; mangler noen, én linje «Har du bilder herfra? Send dem inn.» Trykk åpner bildevisningen (`lightbox.js`), der bildet fyller skjermen. Bildene lages i 400, 800, 1200, 1600 og 2400 px (`lib/images.js`). Siden selv bruker høyst 1600 px. I bildevisningen fyller bildet skjermen (også mobil på tvers og nettbrett), med knapper og bildetekst oppå, og nettleseren velger størrelse etter skjermen og pikseltettheten, opptil 2400 px. Har brukeren slått på datasparing, eller er nettet 2G/3G, hentes høyst 1600 px.
10. **Logg og mer**: Flightlog (`https://flightlog.org/fl.html?l=1&a=22&country_id=160&start_id=<id>`), Paraglidingearth (`https://www.paraglidingearth.com/?site=<pgearth_id>`, bare når `pgearth_id` er satt, ellers utelatt). Deretter stedets egne lenker (`links`: title, text, https-url), for eksempel alpinsenteret med åpningstider for heisen.
11. Bunn: «Foreslå endring» (lenke til skjemaet for GitHub-saker; eget skjema uten GitHub-konto er planlagt, se [docs/arkitektur.md](docs/arkitektur.md#planlagt)), Sist endret (dato og navn fra Git; er endringen gjort av en KI-assistent eller bot, vises den som merget PR-en, se `lib/git.js`), Gjennomgått (manuelt felt, rødt «Ikke gjennomgått ennå» hvis tomt), Kilder (én linje, skilt med «|»), ansvarsfraskrivelse.
- Desktop: to kolonner. Venstre: tittel, kart, adkomst, start, landing, bunn. Høyre: Før du starter (ved siden av tittelen), Fakta, Vær, Bilder, Logg og mer. På mobil står blokkene i samme rekkefølge som i HTML (tittel, Før du starter, venstre kolonne, høyre kolonne, bunn), uten CSS `order`, så skjermlesere og tastatur følger det man ser.
- **Hver opplysning står ett sted.** Siden skal være informativ, men kort. Punkter i kartet har kort navn og stikkord («Toppen. Hovedstarten.»), ikke samme tekst som Start, Landing eller Før du starter; farepunkter viser til Før du starter. Innledningen gjentar ikke Veien opp, og lenker står bare der de hører hjemme (IPPC under Luftrom, Yr via meteogrammet).

## Deling og søk
- Alle sider har Open Graph-tagger (tittel, beskrivelse, bilde, adresse), så lenker får forhåndsvisning på Facebook og Messenger. Stedssider bruker et av stedets egne bilder (oversikt, start eller landing) og innledningen, andre sider `src/assets/img/share.jpg` (1200×630, skjermbilde av forsiden).
- `/404.html`: «Fant ikke siden», lenke til forsiden og liste over alle stedene. Ingen lenke til den gamle oversikten.
- `/sitemap.xml` med alle sider uten `noindex` (stedssider med dato fra Git), og `/robots.txt` som peker på den.

## Design
- Farger: bakgrunn #F3F5F4, tekst #1C2B33, dempet tekst #45545C, linjer #C3D0CF, fjord #2E5E6E, aksent #C24A12 (bare bratte partier i høydeprofilen). Rødt og oransje er ellers forbeholdt fare og vind: valgt sted i kartet er større med en mørk ring utenpå (vurderingsfargen beholdes), knapper er mørke/petrol, posisjonsmarkøren i høydeprofilen er mørk, hovedretning petrol #3D7A8A, mulig lys petrol #8FBCC7 (én farge i tre lysheter, så rosen ikke kan forveksles med vindvurderingens trafikklys), vindvurdering grønn #2E8B57 / gul #D99A1E / rød #C62828 (med fargeblindvennlige farger valgt i menyen: blå #0072B2 / gul #E69F00 / oransjerød #D55E00 / grå, Okabe–Ito; valget lagres i nettleseren som fargemodusen) / grå #7F9396 med tynn mørk kant, og «For mye vind» og «Passer ikke» litt mindre i kartet så vurderingen ikke bare vises med farge, farer-boks #FBE3DA med tekst #6B1A0B, parkering #2F6FB5.
- Skrift: Barlow (brødtekst) og Barlow Condensed (overskrifter), lagt på siden selv fra Fontsource (`@fontsource/*`, bare latin og vektene som brukes), ikke fra Google Fonts.
- Sikkerhet: Content-Security-Policy og Referrer-Policy som meta-tagger i `base.njk`, ingen inline-skript (fargemodus settes av `theme-init.js`). Ny ekstern kilde må legges inn i policyen. Se SECURITY.md.
- Mobil først, lesbart ute i sollys, knapper minst 44 px høye. Mørk modus: valg i menyen oppe til høyre på alle sider med Auto, Lys og Mørk. Auto (standard) følger innstillingen på enheten (`prefers-color-scheme`), valget lagres i nettleseren (localStorage). Skriptet i `<head>` setter `data-theme` før siden tegnes; egne fargeverdier under `:root[data-theme="dark"]`, mørkt kart ved at bakgrunnskartet inverteres med CSS-filter (luftrom, termikk og symboler beholder fargene), popuper og lagvelger forblir lyse.
- Designreferanse: `referanse/prototype/` (prototype-HTML fra designfasen, ikke kjørbar som den er). `referanse/` ligger bare lokalt og er ikke med i repoet (se `.gitignore`), fordi uttrekket fra den gamle oversikten inneholder originaltekster.

## Åpne data
- `/flysteder.geojson` og `/flysteder.kml` lages ved hver bygging (`lib/export.js`, `src/flysteder.geojson.11ty.js`, `src/flysteder.kml.11ty.js`), så de alltid følger stedsfilene. Lenket nederst på forsiden.
- Innhold: hovedstart (retninger, nivå, kategorier, høyde, høydeforskjell, gjennomgått), starter med egen posisjon, landinger, parkering, gangruter (lengde, høydemeter, GPX-lenke) og tegningene, med `site_id`, `site_url` og `source` per objekt. Retningsbuene er ikke med som geometri; retningene står som egenskaper. Stedstekster, farer (også objekter i tegningen med style hazard) og grunneierforhold er ikke med.
- Lisens CC BY 4.0, kreditering «Flysteder: HPGT flysteder (https://flysteder.hpgt.com)» (`LICENSE_DATA.md`).
- Senere: veipunktfil for instrumenter (`.cup`/`.wpt`) på samme måte.

## Språk
- Norsk er hovedspråket, engelsk ligger under `/en/` med egne adresser (`/en/sites/<id>/`, `/en/towers/`). Språkene står i `src/_data/languages.js`.
- All fast tekst ligger i ordbøkene `src/_i18n/<språk>.json`. Tekst som mangler i et språk, vises på norsk.
- Stedstekst oversettes i `src/flysteder/<id>/index.<språk>.md` (bare tekst; data hentes fra `index.md`). Mangler den, vises den norske teksten med en merknad. Se [docs/stedsfiler.md](docs/stedsfiler.md#oversettelse).
- Tall, datoer, klokkeslett og retninger følger språket (NØ/NE, 14.05/14:05).

## Fase 3: NOTAM
- IPPC er eneste autoritative kilde. Venter til vi har en sikker og tillatt måte å hente fra IPPC på.
- Visning som i IPPC: NOTAM-områder som polygoner eller sirkler på kartene, fargede markører per type (militært operasjonsområde, ubemannede luftfartøy, hindringer, advarsler) med forklaring, gyldighet i norsk tid, og lenke til IPPC.
