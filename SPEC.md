# HPGT flysteder – specification

New version of flysteder.hpgt.com. It replaces Lars Sletten's old iframe-based flying site guide, which he has handed over to the club. Target audience: newly qualified PP2 pilots and visiting pilots. Norwegian and English (`/en/`), with a structure for more languages (see [docs/architecture.md](docs/architecture.md#languages)).

## Technical setup
- Static site built with **Eleventy (11ty)**. No server, no database.
- Published to **GitHub Pages** via GitHub Actions on push to `main`. The custom domain `flysteder.hpgt.com` is set in the Pages settings (CNAME).
- `actions/checkout` with `fetch-depth: 0`, so «Sist endret» ("Last changed") per site can be read from Git.
- Maps: **Leaflet**, installed via npm and served from the site itself. On touch screens (`pointer: coarse`) one finger scrolls the page and two fingers pan and zoom the map, so you do not get trapped in the map while scrolling (`useTwoFingers` in common.js). Dragging with one finger briefly shows «Bruk to fingre for å flytte kartet» ("Use two fingers to move the map"). In full screen, one finger pans the map. Default base map: Kartverket's open topographic map. Kartverket's tiles are transparent outside Norway, so OpenTopoMap sits underneath and fills in the rest of the world. Alternative layers: Kartverket's greyscale map (`topograatone`, same service with OpenTopoMap underneath), OpenTopoMap, and satellite imagery from Sentinel-2 cloudless (EOX, 10 m resolution, CC BY-NC-SA 4.0, non-commercial use). Norge i bilder aerial photos are better but require permission (requested from Kartverket). Overlay «Terrengskygge» ("Hillshade") from Kartverket's national elevation model (hoydedata.no, `exportImage` with `skyggerelieff`, one image per tile in Web Mercator), off by default, from zoom 8, multiplied over the map (inverted in dark mode). Map sources are credited.
- The PR check (`pr-check.yml`, job `build`) runs the tests (`npm test`) and builds the site. The build must fail if a site file is invalid (missing `name`, invalid direction code, unknown key, missing image).
- Automatic imports (Kartverket heights, airspace from openAIP) never write to the site files, only to `src/_data/cache/`.
- Airspace is fetched from openAIP (CC BY-NC 4.0) with `npm run airspace`, in one or a few circles covering all launches (openAIP has a strict rate limit and rejects too large a radius, so the circles are at most 150 km), and stored per launch and as `region.geojson` for the map layer. Also fetched by the «Update airspace» workflow (`airspace.yml`) on the 1st of each month. Changes arrive as a PR and are reviewed before merging. The key is stored as the repository secret `OPENAIP_API_KEY`. The site file's `airspace` is only used for sites that have not been fetched yet, and for notes (`note`).

## Content
- One folder per site: `src/sites/<id>/index.md` with front matter + text, and images/GPX in the same folder.
- Fixed file names prefixed with the site id, enforced by the build: images are named `<id>-overview-<nr>`, `<id>-takeoff-<direction>-<nr>` (e.g. `elgen-takeoff-se-1`; the direction may be omitted), `<id>-landing-<nr>` and `<id>-landing-spg-<nr>` (`.jpg`, `.png` or `.webp`). The build finds images by name (`lib/site-images.js`), so the site file has no image list, and a wrongly named image stops the build. Walking routes are named `<id>-route.gpx`, or `<id>-route-1.gpx`, `<id>-route-2.gpx` etc. when the site has several routes. Files from Strava or a camera must be renamed before they are added. Images are imported with `npm run images`, which gives them the correct name, downscales them to at most 2560 px and removes metadata (EXIF/GPS).
- **Naming collected photos** (`lib/photo-name.js`), so site, type and direction can be read from the file name:
  - `<Location>_Takeoff_<Direction>_<Nr>_<Original>.jpg`, for example `Storlitinden_Takeoff_SE_1_DSC04968.jpg`
  - `<Location>_Landing_[SPG_]<Nr>_<Original>.jpg`, for example `Storlitinden_Landing_1_DSC05012.jpg` or `Sollifjellet_Landing_SPG_1_DSC00978.jpg`
  - `<Location>_Overview_<Nr>_<Original>.jpg`, for example `Storlitinden_Overview_1_DJI_0042.jpg` (`Aerial` is also accepted, for photos that already have that name)
  - Location is the site name without spaces, hyphens or æ/ø/å («Melå aksla» → `MelaAksla`; æ can be written ae, a or e, ø as oe or o, and å as aa or a). Direction only on Takeoff: one English code (`N`, `NE`, `E`, `SE`, `S`, `SW`, `W`, `NW`), the direction you face when launching. Landing and Overview have no direction, since it would be arbitrary. **Overview is the overview photo** («Oversikt» on the page, `<id>-overview` in the repository): a photo showing the whole site, ideally the mountain you launch from seen from the air, otherwise from the landing up towards the launch, or the view from the launch. Overview no. 1 is the site's main image and the preview image when the page is shared. `SPG` is an optional tag, only on Landing, for landings that are separate for SPG (Sollifjellet: the SPG landing in the forest). All landings are PG, so that is not written. Nr is 1, 2, 3 … within the same site and type. Original is the camera's file name.
  - `npm run images -- <files or folder>` reads the names, finds the site and imports all the photos. Type, direction, SPG and number are kept in the repository name: `Storlitinden_Takeoff_SE_2_DSC04970.jpg` becomes `storlitinden-takeoff-se-2.jpg`. If any photo is wrongly named (unknown site, Norwegian direction such as SØ, direction on a landing, missing number), or two photos would become the same file, nothing is imported, and the message says what is wrong. Photos that already exist are skipped, so the same folder can be imported several times. `--replace` replaces them.
- Importing single photos without the convention: `npm run images -- <id> <field> <file>`. The photo gets the next free number for the field, without a direction.
- **Photographer and licence** (`lib/photo-credit.js`, `src/_data/photoCredit.json`, `LICENSE_IMAGES.md`): the images are CC BY-NC 4.0. The import removes all metadata (GPS, camera, edit history) and writes back only photographer, copyright, website and licence (EXIF Artist/Copyright in ASCII only; XMP dc:creator, dc:rights, xmpRights:WebStatement, cc:license and website, with æøå and ©). The photographer is read from the original (as Lightroom writes it); otherwise the default is used: Kristoffer D. Hofstad, «© Kristoffer D. Hofstad | Hofstad.NET | @krishofs», https://hofstad.net. Images generated at build time get the same fields. Visible: «Foto: Navn · CC BY-NC 4.0» under the images on the site page and in the image viewer, linking to the photographer's website and the licence. `npm run images` adds photographer and licence to images in the repository that lack them. Originals over 2 MB stop the build. The site only shows versions generated at build time (WebP/JPEG in several sizes), never the originals. The drawn overview images no longer exist: Lars's drawn Google Earth images have been removed, and the map with direction arcs and points has replaced them.
- Front matter follows the structure of the existing files (see `src/sites/elgen/index.md` for a complete example). Keys are in English; values are in Norwegian. `parking` is a list (sites can have several routes, each with its own parking). Each entry under `launches` can have `categories` (PG/SPG).
- Directions are stored as standard codes (N, NE, E, SE, S, SW, W, NW) and shown in Norwegian (N, NØ, Ø, SØ, S, SV, V, NV).
- `status: draft` means the site is shown but marked «Ikke gjennomgått ennå» ("Not reviewed yet"). Once the site has been checked, set `status: reviewed` together with `reviewed.by` (name) and `reviewed.date` (`'2026-09-24'`). The build fails if `status` and `reviewed` do not match.
- Empty fields (`null`) are shown as clear placeholders or omitted, never as guessed values.
- The status page `/status/` shows which sites have been reviewed, and what is missing per site (level, landing (not when `no_fixed_landing: true`), parking, parking text, walking route (not when a parking is within 300 m of the launch and less than 50 m lower, using the height in the parking's `masl`), launch text, landing text, heights, images, airspace, yr_id, flightlog_id, English text and outdated English text). See [docs/operations.md](docs/operations.md#status-page). It is generated automatically on every build, is not linked from the menu and is marked `noindex`. It replaces `MANGLER.csv`.

## Home page
- Title «Hvor står vinden i dag?» ("Where is the wind today?") with «Harstad, Kvæfjord og omegn» above it, and the app icon (`icon.svg`) next to «HPGT flysteder» at the top. A menu button (three lines) at the top right of every page, with a language switcher (Norsk/English, linking to the same page in the other language), colour mode (Auto/Lys/Mørk, i.e. Auto/Light/Dark), a toggle for colour-blind-friendly colours, and «Lenker» ("Links") with an icon before each: «NOTAM og luftrom» (IPPC), «Tårn» (the tower phone numbers) and «Til hpgt.com». «Alle flysteder» is at the top left of the site pages, not in the menu. Open data is linked at the bottom of the home page. «Foreslå endring» ("Suggest a change") is not on the site until there is a form that does not need a GitHub account (see [docs/architecture.md](docs/architecture.md#planned)).
- **«Når kan det passe?»** ("When might it work?") at the top of the **Vær** ("Weather") tab (with a forecast), so the site list is not pushed down: for today and the next two days in the forecast, the sites matching the filters (direction, level, category, search) with the daylight periods where the rating is «Kan passe» (green) or «Usikkert» (yellow) (`dayWindows` in wind.js; daylight = sun above the horizon, midnight sun all day, polar night 10:00–14:00). Most workable hours first; 6 are shown and the rest are behind «Vis n til» ("Show n more"), and sites with only uncertain periods are behind «Bare usikre tidsrom (n)» ("Only uncertain periods (n)"). Clicking the name selects the site. It says so when the forecast ends partway through the day. Tracked as `day-plan/select/<id>`.
- **Site search** at the top of the filters: filters the list and the map as you type, combined with the other filters. Case- and accent-insensitive; æ/ø/å can be written ae/a, oe/o and aa/a («kvaefjord», «hoegfjellet», «blaahatten»); spaces and hyphens are ignored; matches anywhere in the name («solli» → Sollifjellet), the municipality («kvæfjord») or the region («lofoten»). Region parts that are a municipality name («Harstad og Kvæfjord») do not count, so «Kvæfjord» only finds launches in Kvæfjord municipality. Up to 6 matches are shown as buttons right below the field (otherwise the count), and the map zooms to the matches. Enter with one match selects the site; Esc clears. Stored in the URL as `q=`.
- Filters that work together, behind the «Filter» button next to the search (with the number chosen as a badge): **wind direction** (a small wind rose with eight sectors to tap and «Alle» ("All") in the middle; several directions can be chosen, and a site matches when it suits one of them; stored in the URL as `direction=W,NW`), **level** (All, PP2–PP5, shows the selected level and lower), **category** (All, PG, SPG, PPG), and «Bare steder som kan passe» (below). On mobile the filters open as a panel from the bottom with «Vis 12 flysteder» ("Show 12 sites") to close it; on desktop they fold out below the search. With a category selected, the directions of that category's launches are used (`launches[].categories`) in the direction filter, the rose and the wind assessment: SPG on Elgen launches only towards NE–SW. Sites without a recorded level are not hidden by the level filter: they are listed at the bottom under «Nivå ikke satt» ("Level not set"), slightly dimmed on the map, and counted separately («3 flysteder passer filtrene, 25 uten nivå», "3 sites match the filters, 25 without a level").
- Map with all launches as small wind roses (white dividers, dark outline, site name below the roses when zoomed in close; with wind on, also mean wind and gust for the selected time, «5 (8) m/s»; the direction is shown in the rose). Launches that overlap when zoomed out are merged into a cluster showing the number of sites matching the filter (Leaflet.markercluster); clicking zooms in. With wind on, the cluster gets the ring colour of the best rating inside it. Airspace layers as in IPPC can be toggled in the map's layer control: CTA/TMA, CTR, military areas, danger and restricted areas. Off by default, loaded only when turned on («Laster luftrom …» ("Loading airspace …"); on error «Kunne ikke hente luftrom» ("Could not load airspace") with «Prøv igjen» ("Try again")); clicking shows name, class and limits. Attribution «Luftrom: openAIP … Ikke for navigasjon, sjekk IPPC» ("Airspace: openAIP … Not for navigation, check IPPC"). Thermal layers (also on the site pages): «Termikk: skyways» and «Termikk: hotspots» from thermal.kk7.ch (CC BY-NC-SA 4.0, statistics from logged flights, not a forecast), off by default. Precipitation radar from RainViewer as a separate layer (off by default, loaded when turned on): the last 6 frames (10 min apart) as an animation that stops on the last one, «Radar kl. 10.50» below the layer control, «Laster radar …» / «Kunne ikke hente radar» ("Loading radar …" / "Could not load radar") with «Prøv igjen» (timeout 15 s); the frame list is refreshed every 10 minutes. The free tier only has tiles up to zoom 7, which are upscaled. Attribution «Radar: data fra Rain Viewer» (required). MET's radar map (public-wms.met.no) is reserved for Yr, and the radar images in api.met.no are finished images with their own map, so they cannot be used as a layer. Sites that do not match the filter are dimmed. Clicking a launch shows a card with rose, tags, short text, «Se hele stedet» ("See the whole site") and «Se på Flightlog» ("See on Flightlog"). The map opens over the launches in the home region (`homeRegion` in `src/_data/site.js`, «Harstad og Kvæfjord», which also covers Grytøya), not over all sites, so distant sites (Lofoten, Andøya, Andørja, Bjerkvik) do not zoom the map out. They are in the list and the search. Below the zoom buttons: «Vis flysteder i Harstad og Kvæfjord» ("Show sites in Harstad and Kvæfjord"; house icon, back to the home region) and full screen, the same buttons as on the site page (`addViewControls` in common.js).
- **Controls**: the time for the wind assessment is a timeline at the bottom of the map: «Nå» ("Now"), the time shown («kl. 14.00», «i morgen kl. 10.00», «søn. kl. 13.00») and a slider over the hours in the forecast (48 hours). The track is coloured hour by hour with the best rating among the sites matching the filters, with the weekday at each midnight, so you can see when it may work. Stored in the URL as `wind=<hours from now>` (old links with `wind=3`, `6` or `tomorrow` still work). On desktop (mouse), the controls and list are more compact. Mobile keeps 44 px touch targets.
- **Mobile**: the map comes right after the title and stays at the top of the screen while the list scrolls under it, with the search and «Filter» right below it. The map is 300 px, 180 px once the list has been scrolled a bit (back to 300 px near the top), and 130 px while searching (the timeline is then hidden). The space the map gives up is kept as margin below, so the list does not jump. Tapping a site in the list shows it in the map (and a line on the map with «Se ›» to the site page) and marks it in the list with «Trykk igjen for å åpne flystedet» ("Tap again to open the site"); a second tap opens the site page. Tapping a rose in the map scrolls the list to the site and marks it. The map attribution is one line below the map.
- Legend for the rose colours (main direction, possible, not suitable) and the rating colours, in the map status details (below).
- **Wind assessment** at the time chosen in the timeline. Forecast from MET Locationforecast for each launch (`lib/weather/met.js`, 48 hours, fetched by the `weather` job before every build and read by `src/_data/forecast.js`; the site is built twice an hour, but GitHub may delay scheduled runs). The logic is in `src/assets/js/wind.js` and tested in `test/wind.test.js`. Rules in `src/_data/windRules.json`:
  - «For mye vind» ("Too much wind"): mean wind above `maxWind` (7 m/s), or above the site's own limit `wind_limits.max_wind` when set, or gusts above `maxGust` (10 m/s).
  - «Passer ikke» ("Not suitable"): rain forecast, `rainNo` (0.5 mm) or more in the next hour (precipitation from MET, `next_1_hours`), or the direction is neither a main nor a possible direction.
  - «Usikkert» ("Uncertain"): light precipitation forecast (`rainMaybe`, 0.1 mm or more in the next hour), possible direction, mean wind below `minWind` (2 m/s; the direction is then uncertain), the forecast lacks gusts, gusts more than `maxGustSpread` (4 m/s) above the mean wind, or a main direction where the wind is within `sectorMargin` (10°) of a direction that is not a main direction.
  - «Kan passe» ("May work"): otherwise. Missing or uncertain data never improves the rating.
  - Invalid data: an hour where direction or mean wind is not a valid number (missing, NaN, a string, direction outside 0–360, negative wind) counts as no forecast for that site (`windAt` returns null, the page shows «Ingen varsel»). If such an hour reaches `rateWind` anyway, it gives «Passer ikke» with «Mangler gyldige vinddata». Invalid gusts or precipitation count as missing.
  - The card shows wind, time, rating and reason. In the map status details: which time is shown, when MET last updated the forecast (`updated`, the oldest `meta.updated_at` across the launches) and when it was fetched, and sunrise and sunset in the middle of the home region for the day shown, or midnight sun / polar night. Times are always Norwegian time.
  - If the forecast was fetched more than `maxForecastAgeHours` (6 h) ago, the timeline is hidden and the page says the forecast is too old. The age is checked again before every assessment, when returning to the tab and every minute, so a tab left open for a long time turns off the assessment by itself. The assessment is also redrawn when the selected time has moved to a different hour in the forecast (hour change). If the forecast does not cover the selected time, no assessment is shown.
  - **Forecast suggestion**: the switch «Bare steder som kan passe nå» ("Only sites that may work now"; the text follows the selected time) in the filters dims sites rated «Passer ikke» or «For mye vind», as when selecting a direction, and removes them from the list. «Kan passe» and «Usikkert» remain. Sites without a forecast (the fetch failed for that site) are listed separately at the bottom under «Mangler varsel – ikke vurdert» ("No forecast – not assessed"), and slightly dimmed on the map like sites without a level. Works together with the other filters and is off by default. Stored in the URL as `forslag=1`.
  - **Map status**: a pill at the top of the map with how many sites may work at the selected time, with the best rating found (symbol and colour) and the most common direction («✓ 3 kan passe · mest NV»; on desktop also the wind, «Mest V 2–8 m/s, kast 14»). Without a forecast: «Viser 9 av 30 flysteder» ("Showing 9 of 30 sites"). Tapping it opens the details: the wind summary, when the forecast was fetched and which time is shown, the legend and «Hvordan vurderes vind og regn?» ("How are wind and rain assessed?").
  - **Summary** for the selected time (in the status details), for the sites matching direction, level, category and search («For 16 steder som passer filtrene», "For 16 sites matching the filters"): the wind in the area (most common direction, mean wind range, highest gust) and how many sites may work, are uncertain, have too much wind (how many because of gusts or the site's own limit), wrong direction or rain, and how many lack a forecast. If none are suitable, it says why (too much wind, gusts too strong or wrong direction), also in the list when the suggestion is on.
  - The forecast is fetched per site. If one site fails, it shows «Ingen vindvarsel for stedet» ("No wind forecast for this site") and the rest are assessed. If all fail, the timeline is not shown.
  - The map shows a coloured ring, and the sector of the rose the wind comes from is lifted slightly out and filled with the rating colour (no separate wind arrow), also in the rose on the selected site card; the list is sorted by rating. Only a suggestion, never «OK å fly» ("OK to fly").
- List of sites matching the filter, sorted by rating: a small rose for each site (the wind sector in the rating colour and the rating ring, as on the map), the name with the launch height (m asl), the directions, and the rating as a chip with a symbol (✓ ? ! ×) followed by the wind. Without filters or search, the first 5 are shown, and «Vis alle 32» ("Show all 32") shows the rest. The selected site card also shows the launch height.
- **Tabs** with icons: **Flysteder** ("Sites": search, filters and list, with a short line saying it is a rough guide) and **Vær** ("Weather": «Når kan det passe?» and links to Flybart, XCC, Yr and Windy; measured wind from weather stations on the map will go here). The map is always visible. Arrow keys move between the tabs.
- NOTAM and airspace (https://ippc.no) and Towers (a separate page `/tarn/`, `/en/towers/` in English; the old URL `/luftrom/` redirects) are in the menu, with the towers' phone numbers from `src/_data/towers.json` (towers without a number are not shown). The site pages link to the tower page from Luftrom. Flybart and XCC are under Vær.
- Disclaimer, credit to Lars Sletten, open data and statistics at the bottom of the left column (below the list on mobile), folded behind «Om siden: ansvar, åpne data og statistikk» ("About the site"). The short note that it is a rough guide is visible right below the list. The credit is only here, not on every site page.
- Desktop: two columns (left column with tabs | map). The status pill is at the top left of the map, the timeline at the bottom in the middle, and the selected site card at the bottom right (shown when a site is selected, closed with ×). One click in the list shows the site in the map and the card. Search and «Filter» stay at the top of the left column while the list scrolls, as on mobile.
- Markers (46 px): the same rose as in the card and on the site page (`roseSvg` in common.js). With wind on, the ring has the rating colour, and the sector the wind comes from is filled with the rating colour from the centre all the way out to the ring (no wind arrow). In the selected site card, the sector is lifted slightly out instead. Clusters are rounded squares (40 px), so they do not resemble the numbered points on the site pages.
- The status details: the wind line, a colour bar showing the distribution of ratings, and the count per rating with coloured dots. The details (gusts, the site's own limit) are in the colour bar's tooltip. If none are suitable, the reason is shown below.

## Site page – fixed template, in this order
1. **Top**: «‹ Alle flysteder» ("All sites") and the menu. Then the site's first overview image with the region, the name and the key facts as chips (launch m asl, height down, level or «Nivå ikke satt», category, «Kursplass», season, «Ikke gjennomgått ennå» when not reviewed), and the wind rose with the site's directions on the image (only the site's directions; the wind now is in the next part). Without an image, a calm gradient. Then the one- or two-sentence introduction.
2. **«Kan jeg fly her nå?»** ("Can I fly here now?", `site-wind.js`, data in `#site-wind-data`), with the same rules as the home page: the rating now in large type with its symbol and colour (the card's top edge has the colour too), the wind now and the reasons, and today's sunrise and sunset at the launch («Sola opp 07.37, ned 17.46.», «Midnattssol …» / «Mørketid …»; `sunTimes` in wind.js). Then the next 12 hours as cards (hour, symbol, bar for the mean wind with a line for the gust, an arrow for where the wind blows, and «NV 3 (7)»), the site's own wind limit when set (`wind_limits.max_wind`), and folded: «Når kan det passe? Neste 48 timer» (the daylight periods that may work, and 48 hours as bars) and «Detaljer: Yr time for time og høydevind». It says so when the forecast is too old or does not cover the hour.
   - **«Vind over starten (utkast)»** ("Wind above the launch (draft)", winds aloft), folded with the Yr meteogram under «Detaljer: Yr time for time og høydevind», for the launches in `WINDGRAM_SITES` in `lib/weather/open-meteo.js` (currently only Sollifjellet): Open-Meteo (CC BY 4.0) is fetched before the build by the weather module (`lib/weather/`, wind, direction and height at the 1000–700 hPa pressure levels, wind at 10 m, temperature and dew point at 2 m, boundary layer height, CAPE; one retry on 429/connection error, written to `.cache/weather/`), converted to a grid every 250 m up to 3000 m asl plus the launch height (`lib/windgram.js`, wind interpolated in u/v between the levels, surface wind from the terrain or the launch), and drawn as a table with the hours across (`windgram.js`): arrow and m/s coloured by the wind rules, a row for the estimated cloud base (m asl, red below the launch; 125 m per degree between temperature and dew point) and «Termikk til» ("Thermals up to"; the boundary layer), dimming above the boundary layer, a dashed line and cloud at the cloud base, and grey columns when it is dark. Missing when the fetch fails or in the PR check (`FORECAST_OFFLINE`).
   - Yr meteogram linking to Yr (`https://www.yr.no/nb/innhold/<yr_id>/meteogram.svg`, `https://www.yr.no/en/content/<yr_id>/meteogram.svg` in English, with `?mode=dark` in dark mode; attribution «Varsel fra Yr, levert av NRK og Meteorologisk institutt»).
3. **«Før du starter»** ("Before you launch"): only hazards that apply to the whole site. Right after «Kan jeg fly her nå?». Calm amber colour with «!», not red: it is important information for the pilot, not an alarm (red is for «For mye vind»). Hazard points on the map have the same colour. If there are none: «Ingen spesielle farer registrert for stedet.» ("No particular hazards recorded for this site."; neutral box) when the site has been reviewed, otherwise «Farene er ikke gjennomgått ennå. At ingen er registrert, betyr ikke at stedet er uten farer …» ("The hazards have not been reviewed yet. That none are recorded does not mean the site has no hazards …").
4. **Links to the parts of the page** (Start, Kart, Landing, Luftrom, Bilder, Lenker) in a row that stays at the top while scrolling, faded at the edges when it does not fit. The part in view is marked (the last one at the bottom of the page).
5. **Start** (launch): the wind rose with legend, a short text about the launch area and one line per direction group with direction labels in the rose colours, and category tags (PG/SPG) when the site has more than one category, so you can see which launches are used for SPG (for example Sollifjellet: SPG from the top and at the top of the lift). If the site has only one category, no category is set per launch. Launches with the same directions and categories are merged into one line, with their texts listed in the order of the site file (`groupLaunches` in `lib/format.js`); the map still shows each launch where it is. The site page is mainly information about the site, so the wind now is only in «Kan jeg fly her nå?», not per launch.
6. **Kart** ("Map"): the launch as a dot with a white outline in the same petrol blue as the main direction in the wind rose (round, to distinguish it from parking; the directions are shown by the direction arcs and in the tooltip), landing as a dark target, alternative landing as a grey target, parking (blue P). Launches with their own position (`launches[].lat`/`lon`, optional, at most 5 km from `launch`) each get their own dot with their directions in the tooltip; the main launch then represents the launches without their own position, and is not drawn if all have their own position. One dot is the default: directions launched from the same spot belong to the same launch, even when it covers many directions. Own positions are only for launches in a different place (Sollifjellet: the top, the ski centre, the ski slope and the back side). Launches, landing, parking and numbered points are in one layer (Leaflet.markercluster). Launches so close that the dots would overlap are merged into one dot showing the number of launches. When different points overlap (for example landing, P and a number), they are merged into one white box with the same symbols at small size (dot with number of launches, target, P, number), with the names in the tooltip. Tapping the box zooms in until they separate; from zoom 16 everything is shown separately. When zoomed far out (zoom 13 and lower), more are merged, since the boxes are wide. Tapping in the «Punkter i kartet» ("Points on the map") list zooms in until the point is shown on its own. Walking routes from GPX (dashed line). Buttons: directions to the parking (Google Maps), download walking route (GPX).
   - **Direction arcs** (top-down, in the same map): yellow arcs with an arrow and direction label for each direction the site is suitable for, calculated from `wind_directions` and the launch positions (`directionArcs` in `common.js`). If the launches have their own positions, each direction group (launches with the same directions) gets its own arc where the launches are: centred between them, with a radius of the furthest launch + 110 m. Without own positions there is one arc around the main launch (250 m), or around `direction_arc` in the drawing. Dark yellow is a main direction, light yellow possible. The arc is kept at least 60 px on screen and redrawn on zoom; the map zooms out until the arcs and direction labels fit.
   - **The drawing** (`<id>-drawing.geojson`, optional, validated at build time in `lib/drawing.js`, can be drawn in geojson.io): replaces the drawn overview images. `label` (point with title and text), `path` (line, style launch/flight/hazard/info, dashed, arrow) and `area` (area, style hazard/launch/landing/info), and an optional `direction_arc` (center, radius). Only content the club has confirmed is added.
   - **Points on the map**: numbered points that show title and text when tapped, and a numbered list «Punkter i kartet» below the map. Tapping in the list moves the map there and shows the text; tapping a point highlights it in the list; hazards are shown as a light square with a red border. The number on a group of merged launches is white with an orange border, so it is not confused with the points.
   - **Show the whole site**: a button with a house icon below the zoom buttons, which returns to the view with everything (launches, landing, parking, walking routes and direction arcs).
   - **Full screen**: a button below «Vis hele stedet» ("Show the whole site") that lays the map over the whole page (not the browser's full screen, so it also works on iPhone). Esc or the button again closes it. The view adjusts when the map changes size.
   - **Zoom**: the mouse wheel scrolls the page; with Ctrl (Cmd on Mac) it zooms the map, and without it a short hint is shown. The zoom buttons and +/- on the keyboard when the map has focus work as before.
   - **Elevation profile** near the top of «Landing og adkomst» (open) when the site has a walking route: distance/height, sections steeper than 25 % highlighted in the accent colour, a slider (and drag/touch in the profile) that moves a marker along the route on the map and shows distance, height and gradient. Tabs when the site has several routes. A short summary below (km, from–to m asl, how much is steeper than 25 %). Heights should come from Kartverket, with GPS heights as fallback.
   - Time under «Landing og adkomst» is moving time from GPX (without breaks), rounded to 5 min. If the site has one walking route, length, elevation gain and time are shown as three figures at the top of «Landing og adkomst» («1,5 km · 330 m · 35 min») and are not repeated in the rows below.
7. **«Landing og adkomst»** ("Landing and access"): the glide from launch to landing («1,6 km, 350 m ned, 4,6 : 1»), the walking route as three figures when there is one, Parking, «Veien opp» ("Way up"), Time, the landing text, the same note for all sites («Se alltid over landingen før du flyr. Lander du på et jorde, må det være avtalt med bonden, og gresset må ikke være høyt.»), directions and GPX buttons. The elevation profile of the walking route is open, right below the glide and the walking figures.
8. **Luftrom** ("Airspace"): only the ceiling above the launch, the lowest fixed airspace above the launch site, as a schematic height profile (`lib/airspace-profile.js`, SVG at build time: the airspace band with name, class and floor at the top, terrain from launch to landing, and a thin arrow from the launch to the floor with the height in metres; orange «start over grensen» when the launch is above the floor; not to scale, only fixed airspace). Airspace from the ground is said in text. Below it one line: the date of the last fetch, «Sjekk alltid IPPC før du flyr.» and a link to the tower phone numbers. Nearby airspace is only shown when the site file has a note about it.
9. **Bilder** ("Images", open also on mobile): overview image no. 1 large at the top (the same as the share preview image), the first launch and first landing image smaller below. Captions «Oversikt», «Start mot SØ», «Landing» or «SPG-landing» ("Overview", "Launch towards SE", "Landing", "SPG landing"). If the site has more images, «Se alle N bilder» ("See all N photos") opens the image viewer with all of them, in the order overview, launch, landing (SPG landing last). Only existing images are shown; without any, «Ingen bilder ennå.» ("No photos yet."). A way to send in photos comes with the form without a GitHub account. Tapping opens the image viewer (`lightbox.js`), where the image fills the screen. Images are generated at 400, 800, 1200, 1600 and 2400 px (`lib/images.js`). The page itself uses at most 1600 px. In the image viewer the image fills the screen (also mobile in landscape and tablets), with buttons and caption on top, and the browser picks the size from the screen and pixel density, up to 2400 px. If the user has enabled data saving, or the connection is 2G/3G, at most 1600 px is fetched.
10. **Lenker** ("Links", open also on mobile, in the right column on desktop): «Vær» with Yr (when the site has `yr_id`) and Windy (pin on the launch: `https://www.windy.com/<lat>/<lon>?<lat>,<lon>,12`): only links for this launch, so Flybart (a few weather stations) is under Vær on the home page and not here; «Logg» with Flightlog (`https://flightlog.org/fl.html?l=1&a=22&country_id=160&start_id=<id>`); and «Mer om stedet» with the site's own links (`links`: title, text, https URL), for example the ski centre with lift opening hours.
11. Footer: «Sist endret» ("Last changed"; date and name from Git; if the change was made by an AI assistant or bot, it is shown as the merged PR, see `lib/git.js`), «Gjennomgått» ("Reviewed"; manual field, red «Ikke gjennomgått ennå» if empty), «Kilder» ("Sources"; the source names on one line, «Flightlog, Kartverket, openAIP, GPS-spor og lokalkunnskap», with what each field comes from folded under «Detaljer»), disclaimer.
- Mobile: the three things you need on the way at the bottom of the screen: «Veibeskrivelse» ("Directions"), «Kart» and «GPX». Not on desktop.
- The level, category, season and heights are in the top part; there is no separate «Fakta» part.
- Desktop (from 1100 px): two columns below the image. Left: the introduction and «Kan jeg fly her nå?», then the links row, Start, Kart and «Landing og adkomst», and the footer. Right: «Før du starter» beside the top, then Luftrom, Bilder and Lenker. Mobile: one column in the same order as the HTML (introduction, «Kan jeg fly her nå?», «Før du starter», links, Start, Kart, Landing og adkomst, Luftrom, Bilder, Lenker, footer), without CSS `order`, so screen readers and keyboard navigation follow what you see.
- **Each piece of information is in one place.** The page should be informative but short. Map points have a short name and keywords («Toppen. Hovedstarten.», "The top. The main launch."), not the same text as Start, Landing or «Før du starter»; hazard points refer to «Før du starter». The introduction does not repeat «Veien opp», and links only appear where they belong (IPPC under Luftrom, Yr via the meteogram).

## Sharing and search
- All pages have Open Graph tags (title, description, image, URL), so links get a preview on Facebook and Messenger. Site pages use one of the site's own images (overview, launch or landing) and the introduction; other pages use `src/assets/img/share.jpg` (1200×630, a screenshot of the home page).
- `/404.html`: «Fant ikke siden» ("Page not found"), a link to the home page and a list of all sites. No link to the old guide.
- `/sitemap.xml` with all pages without `noindex` (site pages dated from Git), and `/robots.txt` pointing to it.

## App and offline
- Installable as an app: a web app manifest per language (`/manifest.webmanifest`, `/en/manifest.webmanifest`, `lib/pwa.js`) with the front page in that language as start page, and icons made from `src/assets/img/icon.svg` (`node scripts/app-icons.mjs`).
- A service worker (`/sw.js`, from `lib/service-worker.js`) makes visited pages work without a connection: pages network first (the stored copy after 4 s on a slow connection, and the offline page «Du er offline» / «You are offline» for a page not stored), own CSS, JS, fonts and images stale-while-revalidate, GPX/GeoJSON/KML network first, and the Kartverket map tiles the visitor has seen, at most 300. Nothing is downloaded in advance except the front pages, the offline pages and the scripts. GoatCounter, Yr and other map layers are never stored.
- While offline, a notice at the top says the page may be out of date. The forecast is part of the stored page, so the wind assessment turns itself off when it is older than `maxForecastAgeHours` (`isStale`).

## Design
- Colours: background #F3F5F4, text #1C2B33, muted text #45545C, lines #C3D0CF, fjord #2E5E6E, accent #C24A12 (only steep sections in the elevation profile). Red and orange are otherwise reserved for hazards and wind: the selected site on the map is larger with a dark outer ring (the rating colour is kept), buttons are dark/petrol, the position marker in the elevation profile is dark, main direction petrol #3D7A8A, possible light petrol #8FBCC7 (one colour in three shades, so the rose cannot be confused with the wind assessment's traffic lights), wind assessment green #2E8B57 / yellow #D99A1E / red #C62828 (with colour-blind-friendly colours selected in the menu: blue #0072B2 / yellow #E69F00 / vermilion #D55E00 / grey, Okabe–Ito; the choice is stored in the browser like the colour mode) / grey #7F9396 with a thin dark outline, and «For mye vind» and «Passer ikke» slightly smaller on the map so the rating is not shown by colour alone; hazard box #FBE3DA with text #6B1A0B; parking #2F6FB5.
- Fonts: Barlow (body text) and Barlow Condensed (headings), served from the site itself via Fontsource (`@fontsource/*`, only Latin and the weights used), not from Google Fonts.
- Security: Content-Security-Policy and Referrer-Policy as meta tags in `base.njk`, no inline scripts (the colour mode is set by `theme-init.js`), and the manifest and service worker only from the site itself. A new external source must be added to the policy. See [SECURITY.md](SECURITY.md).
- Mobile first, readable outdoors in sunlight, buttons at least 44 px tall. Dark mode: a choice in the menu at the top right of every page with Auto, Lys and Mørk (Auto, Light, Dark). Auto (default) follows the device setting (`prefers-color-scheme`); the choice is stored in the browser (localStorage). The script in `<head>` sets `data-theme` before the page renders; separate colour values under `:root[data-theme="dark"]`; dark map by inverting the base map with a CSS filter (airspace, thermals and symbols keep their colours); popups and the layer control stay light.
- Design reference: `referanse/prototype/` (prototype HTML from the design phase, not runnable as is). `referanse/` is local only and not in the repository (see `.gitignore`), because the extract from the old guide contains original texts.

## Open data
- `/flysteder.geojson` and `/flysteder.kml` are generated on every build (`lib/export.js`, `src/sites.geojson.11ty.js`, `src/sites.kml.11ty.js`), so they always follow the site files. Linked in the menu and at the bottom of the home page, with «Om dataformatet» ("About the data format") linking to [docs/open-data.md](docs/open-data.md). The KML file is self-explanatory: the names give site and type («Elgen – start», «Elgen – start SPG (NØ, Ø, SØ)», «Elgen – hovedlanding: …», «… – alternativ landing: …», «… – parkering», «… – gangrute»), with Norwegian directions, descriptions per type, a link to the site page and an explanation of the structure at the top of the file. Walking routes are rounded to 0.1 km and whole metres of elevation gain.
- Content: main launch (directions, launch groups per category `launch_groups`, level, categories, height, height difference, reviewed, municipality), launches with their own position, landings, parking, walking routes (length, elevation gain, GPX link) and the drawings, with `site_id`, `site_url` and `source` on each feature. The direction arcs are not included as geometry; the directions are properties. Site texts, hazards (including drawing features with style hazard) and landowner information are not included.
- Licence CC BY 4.0, credited as «Flysteder: HPGT flysteder (https://flysteder.hpgt.com)» (`LICENSE_DATA.md`).
- Later: a waypoint file for instruments (`.cup`/`.wpt`) in the same way.

## Languages
